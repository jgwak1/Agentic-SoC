- Scenario: Suspicious Cloud Resource Discovery
- Primary tactic: Discovery
- Relevant ATT&CK techniques: 
                  "T1580 - Cloud Infrastructure Discovery"
                  "T1619 - Cloud Storage Object Discovery"       
- Secondary tactic: Collection (if discovered resources are subseuqently accessed for data)

- Observed: An AWS identity performs unusual resource-enumeration activity across cloud infrastructure or storage resources.
- Benign hypothesis: An authorized user or service is enumerating cloud resources for a legitimate purpose such as inventory management, troubleshooting, deployment, auditing, or checking available resources.
- Malicious hypothesis: An adversary using a compromised or unauthorized AWS identity is enumerating cloud infrastructure or storage resources to identify targets for subsequent access, collection, or lateral movement.

Investigate
-- Who / Actor: Which AWS identity or session performed the discovery activity, and what is its normal role?
               (e.g., IAM user, assumed role, service account, session identity, normal permissions and responsibilities)

-- When / Time: When did the discovery activity occur, and does its temporal pattern match expected behavior?
               (e.g., normal inventory schedule vs. unusual timing, sudden burst of enumeration, or previously unseen low-and-slow discovery activity)

-- Where / Origin: Where did the discovery requests originate, and is the origin expected for this actor?
                  (e.g., source IP, AWS region, corporate/VPN network, unusual geographic or network origin)

-- How / Mechanism: How was the identity able to perform the discovery, and which APIs or privilege path were used?
                     (e.g., DescribeInstances, ListBuckets, ListObjectsV2, or low-privilege user → unexpected AssumeRole → privileged role → broad resource discovery)

-- What / Action: What resources were discovered, how broad was the enumeration, and what actions followed?
                  (e.g., EC2 instances, VPCs, databases, S3 buckets/objects; enumeration followed by GetObject, resource access, or other sensitive actions)

-- Why / Context: Does the surrounding context provide a legitimate explanation for the discovery activity?
                  (e.g., known inventory job, approved troubleshooting or deployment activity, expected administrator behavior, or no legitimate reason for broad enumeration)

-- Verdict: Benign / Malicious / Insufficient evidence
            (e.g., benign if actor, timing, origin, permissions, and follow-on activity match an expected workflow; malicious if unauthorized discovery and suspicious subsequent access are supported by the evidence)
